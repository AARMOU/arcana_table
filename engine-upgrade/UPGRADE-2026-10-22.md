## Test gates

1. Detect each upstream/patch conflict **without** accepting patch fuzz, silent skip, or reverse-apply as success.
2. Rebuild matching `mtg-sdk`, `mtg-sdk-tooling`, `rules-engine`, and `ai` binaries and verify production class identities and Java 17 bytecode.
3. Run upstream full `:rules-engine:test`, `:mtg-sets:scenarioTest` and `:ai:test`. Every failure must be investigated, not suppressed.
4. Regenerate entire card export and verify all entries round-trip; retain the Arcana custom-card data.
5. Compile against the rebuilt runtime and run `:custom-cards:test`, `:app:testDebugUnitTest`, `:app:lintDebug`, `:app:assembleDebug`.
6. Run high-trigger, high-token, priority/autopass and AI stress cases; compare baseline and candidate on identical fixtures and inspect legal-action/trigger parity, not timing alone.
7. Only after all gates pass, seek explicit approval before replacing shipped binary artifacts, publishing an APK, or merging production code.

CI job is intentionally read-only and produces evidence artifacts. If a mandatory patch fails the preflight, subsequent build stages must not run using a partial or mixed engine.
