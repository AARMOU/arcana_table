Tutorial design

Two tutorials that run on top of the real app screens. Try them in the phone: tap, or press and hold (right-click on desktop) when a step asks.

How the tutorial is laid out

        
New players need to finish one real turn fast. Returning players need a reference they can dip into. One long tour serves neither, so the tutorial splits into two tracks that share one engine.

        

          

            
Quick Start

            
~3 min · offered on first launch

            
One scripted turn against a passive opponent: play a land, make mana, cast a creature, read a card, pass priority. Every step waits for the player to do the thing.

          

          

            
Field Guide

            
7 chapters · Home → Tutorials

            
Covers every control on the home screen, main menu, game setup, board, cards, priority and deck library. Chapters are short, independent and tick off as you finish them.

          

        


        
Principles

        
    
          
  • Coach marks on the real UI. A spotlight dims everything but the control being taught. No separate slideshow screens that drift out of date.
    • 
          
  • Learn by doing. Action steps only advance when the player performs the action. Taps elsewhere shake the tip instead of breaking the lesson.
    • 
          
  • One idea per step. A title and at most two sentences. Long rules explanations go behind "hold to read".
    • 
          
  • Always escapable. Skip on every step, replay from Tutorials, progress saved per chapter.
    • 
          
  • Deterministic sandbox. Tutorial games use a fixed seed, fixed hands and an opponent that only passes, so Argentum's rules engine runs for real but nothing surprises the script.

How it maps to the Android code

        
    
          
  1. TutorialStep data: id, screen, target id, title, body, and how it advances (next, tap, hold, or an engine event). The box above shows the live step.
    2. 
          
  2. Steps live in JSON under assets/tutorials/, so new chapters are content edits that GPT can write and review without touching engine code.
    3. 
          
  3. A Compose modifier, Modifier.tutorialTarget("hand-forest"), registers each control's bounds so the overlay can find it.
    4. 
          
  4. TutorialController is a small state machine. It listens to the UI for taps and to Argentum for events like land played, mana added and priority passed.
    5. 
          
  5. SpotlightOverlay draws the dim layer with a cutout and the tip card, and swallows input outside the target.
    6. 
          
  6. Completed chapter ids are stored in DataStore. First launch checks it and offers Quick Start once.
    7. 
        


        
Build order

        
    
          
  1. Controller, overlay and target registry, plus the Quick Start script.
    2. 
          
  2. Tutorial sandbox game: fixed seed and a passive opponent in Argentum.
    3. 
          
  3. Field Guide hub and chapters, one at a time, checked against the real screens.
