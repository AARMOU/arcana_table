## Manual source-validation procedure
Run `Next APK combined-source validation (manual, no publishing)` from the exact integration-preflight branch. Input `include_online_multiplayer=true` (default) exercises the maximal combination; `false` isolates the two-player baseline + upgrade automation + UI + AI and preserves the prior production scope. **Do not dispatch** without owner approval for a CI compile/build.

The workflow takes the existing #260 fail-closed upgraded Argentum/Eldrazi Build 134 runbook, commits its temporary merged working tree locally, then merges #273, #277, #270 and optionally #268 at pinned SHAs. It refuses unknown Git merge conflicts rather than choosing a side automatically. It checks exact commit ancestry/provenance, runs Android regex/branding, real engine/custom cards, offline AI, tutorial debug and release tests, release feature boundaries, lint, unsigned release APK/AAB compilation, and package/provenance checks. Online mode additionally runs the Worker strict TypeScript and local three-guest directed-relay privacy proof. No uploadable APK is created by this workflow.

**Important:** GitHub CI checks on individual PRs do not certify that these combined source trees merge, compile, or are playable together. In particular `HomeScreen.kt`, `TableController.kt`, and `TableOverlays.kt` are touched by multiple active lanes, and multiplayer's normal-app availability conflicts with the old two-player release boundary. A red integration attempt is a required blocker, not permission to discard test coverage or forcibly take one branch.

## Finish criteria before authorizing a test APK
1. Run and close all integration conflicts on an isolated source branch with exact-head provenance; preserve the release scope policy or obtain an explicit owner-approved change.
2. Complete the exact combined validation job: updated engine/custom cards, offline AI and target/privacy cases, complete Android debug/release suites, all hardcoded Build 134 assets and launcher logo, no unexpected skipped critical cases, debug and unsigned release packaging.
3. If shipping four-player internet, verify the Worker version supports directed `relay:1`, has separate deployment approval, and conduct cross-network, four-physical-seat, reconnect, hidden-hand privacy, and Fold-portrait tests before declaring multiplayer functional. Do not deploy from the compilation workflow.
4. Only with a separately approved APK build, generate and distribute a **debug** test APK, record package ID/version, content SHA-256, engine SHA and signing-certificate identity. Keep production upload-key signing and Play publication separately approved. Follow physical D01–D10 checklist from #269 before release.
